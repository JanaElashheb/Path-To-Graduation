# Path to Graduation

*Path to Graduation* (or *Path to Grad*) is a single-player platformer that currently allows the user to learn and play through (two) different 4U Canadian level math courses.

## Features

The program contains of a handful of features including:
- two currently working math strands - Calculus and Vectors (MCV4U) and Data Management (MDM4U) - the user can play through
- a trio of unique enemies for the different math strands, each representing one part of a three-tier difficulty scale
- the ability to revisit, redo, and save the various questions the user comes across, if they have or have not answered the question correctly. This is done through a "Question Book" and "Challenge Bank"
- the ability to revisit a "Concept Book" that contains the various unlocked lessons from every unit they have collected
- the user is able to collect a set of items that contribute to how they can interact with and solve questions. Primarily, they can collect health potions, hint spells, and skip stones, which allow them to heal as they fight enemies, skip over questions, or utilize hints
- hints are also automatically provided for harder questions in order to ensure the user is given maximum ability to comprehend and process the content required of them to complete difficult questions
- the user can give up a fight if they wish, but they still lose items, which is different from skipping a question

## Installation

Access the following file and download the .zip file: [Path to Graduation](https://drive.google.com/drive/u/3/folders/1p3qKG2iM7LE6GcaoTcYYemXr9HqRYHxg).

Extract the files in your hard drive folder of choice. You can delete the excess folders after you've moved the unzipped folder labelled "Path to Grad" to wherever you want. Click on `main.py - Shortcut`, and your game should launch!

Note the possibility of your virus program grabbing the file and scanning it for a virus. Ideally, it should detect no issues with the program and O.K. it.

## Known Bugs

- The item acquisition and loss following the player losing, dying or winning either take too much/too little or excessively of one item, especially if the user only has that item. This has two unintended side effects: the user will either have an influx of items, or - as merchants are not implemented - this can provided difficulties with maintaining items.
- Sometimes the challenge bank doesn't work when you input a question you'd typically be able to access. Closing it and re-opening it typically works.
- Sometimes moving between worlds doesn't really allow the world to return to the previous world as the scroll value gets messed up somewhere, but this could or could not be a solved issue. But this could also be that sometimes when the player revives, they don't start in the exact position of their last saved checkpoint, but at the beginning of the map.
- When you lose an item, the message tells you lost more than you may actually have.
